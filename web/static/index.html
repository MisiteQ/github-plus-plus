系统级 HTTP 代理

开启后会在 /etc/profile.d/ghpp-proxy.sh 写入 http_proxy / https_proxy 指向 127.0.0.1:7710，所有新登录 shell 启动的软件默认走加速器。 加速器仅对 GitHub 相关域名走镜像加速、其他流量透明转发，一般不影响正常联网； 但若加速器进程异常，可能影响新 shell 的网络访问。 已运行的进程不受影响，需重启对应软件才生效。

适用于 apt / yum / wget / curl / git / pip / npm / go modules 等读 http_proxy 环境变量的工具， 以及飞牛本机所有通过 shell 启动的命令行软件。 Docker 容器需在飞牛 Docker 界面重启容器让其继承（见下方场景说明）。

三种被动加速方式

按场景选用，可叠加
◎
hosts 加速（推荐，对飞牛本机 GitHub 访问全局生效）

开启后 NAS 本机 /etc/hosts 把 github.com 等域名解析到 NAS 本机， 飞牛系统应用、命令行工具、任何走系统 DNS 的软件访问 GitHub 都自动加速，无需软件配置。

⬢
Docker 加速（对 docker pull 全局生效）

点下方按钮自动写入 Docker 配置并重启 Docker，所有 docker pull / docker compose pull 自动走加速。飞牛应用中心装的 docker 应用拉镜像也会走加速。

⊞
系统级 HTTP 代理（对读环境变量的软件生效）

见上方开关。apt / yum / wget / curl / git / pip / npm / go modules 等工具会 自动读取 http_proxy 环境变量走加速，无需单独配置。

我的软件该用哪种方式？

按访问方式对号入座，不限软件
下表按软件访问 GitHub 的方式分类，不限于具体软件名字—— 无论你装的是 emby / jellyfin / homeassistant / halo / 青龙 / n8n / alist 还是任何其他应用， 只要它的网络访问属于下列方式之一，就已被对应开关覆盖。
方式一：软件走系统 DNS 访问 GitHub

绝大多数桌面应用、飞牛系统服务、带 Web 界面拉插件/字幕/资源的软件（如 emby/jellyfin 插件、各种 NAS 应用的更新检查）。 开启 hosts 加速即可，github.com 等域名被解析到 NAS 本机自动走加速，无需改软件配置。

方式二：软件用 docker pull 拉镜像

所有 docker pull / docker compose pull，包括飞牛应用中心装的 docker 应用拉镜像、青龙/青龙面板更新、任何 compose 堆栈拉镜像。 点上方 一键应用 Docker 配置 即可，registry-mirrors 自动写入 daemon.json。

方式三：软件读 http_proxy 环境变量

命令行工具与包管理器：apt / yum / wget / curl / git / pip / npm / go install / cargo 等。 开启 系统级 HTTP 代理即可，新 shell 启动的软件自动读取 http_proxy 走加速。

方式四：软件是 Docker 容器且访问 GitHub（非 pull 镜像）

容器内软件不走宿主 hosts 也不读宿主 profile.d，如 homeassistant HACS 商店、容器内 git clone GitHub 仓库等。 开启系统代理后，在飞牛 Docker 界面把容器重启一次让其继承 http_proxy（需容器内软件支持读 http_proxy）。

不确定属于哪种？三个开关全开最稳。hosts 加速 + Docker 加速 + 系统代理同时开启， 覆盖所有四种访问方式，互不冲突，任何第三方软件访问 GitHub 都会被动走加速。

后台运行

关闭软件与登出飞牛账号后保持服务运行

开启后，加速服务进程异常退出时由看门狗 3 秒后自动拉起，配合 setsid 脱离会话让关闭桌面窗口与登出飞牛账号都不再中断加速； 关闭后，进程崩溃时看门狗自己也会退出，需要手动启动服务才会恢复。
